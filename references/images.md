# Lesson images

**Generate and display at least one actual instructional image for every lesson explanation, including each concept or mini-concept explanation.** Match its form, detail, and generation effort to what is being taught. A rendered diagram or chart counts when the host actually displays the image. Plain tables, code, or text diagrams may supplement it but cannot replace it.

## Choose the image for the idea

Choose the image that best conveys the current idea, balancing explanatory value with likely generation time. Identify what the learner should notice or understand from it, then select a representation that makes that insight easy to see. Make this choice yourself using the lesson, the learner's needs and feedback, and the host's capabilities; routine lessons need no image-style questionnaire.

Use a quick image when it communicates the idea well. Spend more time on an illustration, composition, or useful detail when it makes the explanation meaningfully clearer. When several approaches convey the idea equally well, favor the quicker route. Use observed tool responsiveness when weighing delay, and base any time estimate on actual session behavior. Keep labels and detail focused enough to remain readable.

## Use purposeful variety

Consider recent lesson images and avoid repeatedly choosing the same layout or visual form by habit. Draw from a broad palette: annotated scenes, cutaways, comparisons before and after a change, visual metaphors, short visual stories, close-ups, timelines, maps, charts, and diagrams. These are options to choose from, not a fixed rotation or a mapping of whole subjects to formats.

Be somewhat creative: let objects, positions, relationships, or changes carry the teaching point. Use metaphors with clear mappings to the concept and explain any important limits. Keep familiar examples, symbols, and labels when they help continuity, while varying the perspective or composition when it improves understanding. Generate or render a new or updated image for the current explanation; unchanged reuse alone does not meet the requirement.

Apply feedback about disliked images by reconsidering the representation and what it communicates, beyond changing colors or decoration. Choose one promising approach before generating; multiple candidate images are not required. Avoid needless extra versions or novelty that distracts from the lesson. For less waiting, choose a quicker image approach that still conveys the meaning. Honor explicit requests for text only, fewer images, or a specific format within their scope.

## Use the host's capabilities

Choose a supported image route that suits the selected representation: native diagram or chart rendering, available drawing tools, or the host's normal image generator. Follow the host's tool and delivery requirements. Waestro requires no particular provider, tool name, API, file format, or separate installation.

Display the actual image. Diagram source, plain tables, code snippets, ASCII diagrams, prompts, filenames, bare links, and captions alone do not count as image delivery. They can be rendered into a useful image or included as extra teaching material.

- **Concept teaching:** generate and display the image even when the explanation ends with an ungraded comfort question.
- **Learner-response tasks:** keep questions, practice exercises, checks, quizzes, exams, and homework in separate text-only turns. Keep answer-revealing aids in teaching turns, separate from independent tasks.
- **Other turns:** feedback, readiness, setup, navigation, or progress updates alone need no image. If the turn teaches another concept, apply the image requirement.

## Create, check, and present

1. **Prepare accurate content.** Check the lesson facts, example, labels, and intended relationships before creating the image.
2. **Generate or render the image.** Use an available image generator or renderer to create the current lesson's image. Native automatic display is suitable; a separate inspection tool is not a prerequisite.
3. **Check what is accessible.** Check the actual image's labels, values, relationships, arrows, legibility, and meaningful counts or proportions. Inspect rendered output before or after display as supported. A prompt or tool-success message alone does not establish visual accuracy.
4. **Correct meaningful errors.** Repair misleading content; a simpler accurate replacement image is suitable. Explain corrections to already shown errors and replace the image when supported. If repair fails, identify the error and try a simpler newly generated or rendered replacement, checking it when possible; otherwise follow the failure rule below.
5. **Show and explain the image.** Use the host's normal image presentation; native automatic display counts as delivery and needs no duplicate embed or separate file. Put the explanation before or after creation as supported, showing what to notice and how it connects to the concept. Keep the ordinary mini-concept pace.

If the selected route is unavailable or fails, try another available image-generation or rendering route. If no image can actually be created or displayed, state the specific limit and use a verified text or table fallback; make clear that the lesson's image requirement could not be met. When displayed output is unavailable for inspection, briefly disclose that limit and keep the explanation grounded in checked content. Never claim an image was generated, displayed, inspected, or corrected without evidence.

The lesson turn is ready when its explanation and newly generated or rendered image are presented, with available accuracy checks completed. If an image is absent, account honestly for an explicit request for text only or fewer/no images, or an actual generation/display limit. A request for a table or less waiting alone does not waive image generation. Count answer-revealing help as assistance under [Fair tasks and learning evidence](../SKILL.md#fair-tasks-and-learning-evidence). Preserve previously delivered visual tasks under [Portable record and storage](progress.md#portable-record-and-storage); the text-only task default does not authorize rewriting saved work.
